# 多账号项目：应用间迁移与自动填充验证（1.0.316）

日期：2026-10-02。测试使用已有公共 Android 32 x86_64 模拟器的独立合成测试用户 10。没有清空应用、数据库或公共 AVD 数据盘。所有测试账号、密码、OTP 和文件均为合成样本。

## 本轮修复

- 应用间导出按实际密码行输出一个 CXF Item / 一个 basic-auth，保留账号与密码对应关系。接收方请求 TOTP 时，在同一 Item 附带该行的标准 TOTP。补齐 MDBX/KeePass 原生 OTP 的读取和旧加密用户名的解密。
- 不把 HOTP/Steam/MOTP 或不支持的参数转换为另一种验证码；在确认导出前提示不能传输的关联 OTP 数量。接收应用不请求 TOTP 时也会提示。
- 系统候选和手动选择页区分同账号的多个密码；显示序号不进入填充值。旧加密用户名在 IO 阶段解析显示值，不修改交给填写/复制动作的原始记录。
- 原有导入回归发现：密码本身是密文格式字符串时，MDBX 可能重复解密。修复为明确的新写入正文标记，导入只去掉已知的一层包装；旧格式的嵌套密文迁移继续保留。测试覆盖后续修复扫描与再次编辑，不能把原值误改。

## 真实系统迁移

普通版通过 Google 应用间凭据交换选择器，选择 Monica，确认接收应用身份，重新验证主密码，再确认导出。接收端是独立安装、独立 UID 的 CXF 测试应用，使用 AndroidX 的 `importCredentialsAsync`；它使用独立 JSON 检查器，不调用 Monica 编解码器。

结果：接收 2 个账号的 4 个密码和 4 个正确配对的 OTP。包括中文、空格、特殊字符、SHA1/6位/30秒与 SHA256/8位/60秒两组参数。导出前后源 KDBX 文件逐字节一致。调用者、签名、URI 所有权和请求类型的安全回归也通过。

F-Droid 不提供 Google Provider Events 入口，本轮未向其加入该入口；仅同步通用格式、存储与自动填充修复。

## 失败记录与修复

所有失败日志保留，未把失败或跳过计为通过。

1. 首轮系统填充测试的通知标题和候选滚动处理不符合当前页面；修复测试定位，同时修复手动选择页旧加密用户名的显示。三条真实填充路径重跑通过。
2. F-Droid 首轮既有密码正文边界回归失败，定位为 MDBX 重复解密；修复生产代码后两版重跑通过，并扩展到修复扫描和编辑场景。
3. 混合运行旧 IME 测试时无法找到字段/数字键。旧测试使用隐式 shell 用户且未清除测试 Activity 任务；测试改为显式用户、全新任务实例及一致的可访问性窗口标志，普通版重跑 2/2 通过。F-Droid 的选中账号用例仍找不到按钮，截图确认正确卡片已展开，但按钮在有原有数据的列表视口下方。测试补上真实列表滚动，不删原有数据，不修改生产键盘来迁就测试。两版带滚动的最终重跑均为 2/2 通过。
