# Android 暂缓接入 Glitter（1.0.317）

## 当前客户端行为

普通版和 F-Droid 的本地、远程创建页面统一提供 Sky、Multi、Power。保留动态星光、连续拖动、松手吸附、点击过渡和跨档触感。

Glitter 枚举值仅用于识别格式和旧记录。移除专用内存检查、创建要求、专用文字保护界面及独立新增路由；普通原生数据库编辑器继续用于支持的数据库。

旧 Glitter 数据库不会自动降档、转换或删除。它们仍留在管理记录中，显示暂不支持；不作为默认库、保存目标、同步目标或普通列表来源。旧保存目标会得到明确提示，不跳入独立编辑器。

客户端创建及已登记数据库操作在执行前拒绝 Glitter。文件导入在原生打开和密码派生前，只读检查公开的 `vault_meta.default_tiga_mode` 标识；原生 MDBX 格式与 JNI 库保留 Glitter 能力。

## 验证

两版最终 Debug 构建成功，每版 **10 项 JVM 测试、32 项设备测试**通过，合计 **84 项通过、0 失败、0 跳过**。重复运行未累计。

| 覆盖 | 每版数量 |
| --- | ---: |
| 档位选择、客户端副本限制、同步资格、资源校验（JVM） | 10 |
| 三档滑块动效与输入 | 13 |
| 创建表单和旧目标拦截 | 4 |
| 客户端拒绝、文件保留与原生兼容 | 4 |
| 普通原生条目、附件及编辑器 | 4 |
| 保存、重开与同步状态 | 7 |

覆盖范围：三档滑块实际中间帧、星光裁剪、反馈与减少动画、RTL/键盘、大字体表单、旧保存目标和旧硬件凭据提示、客户端创建拦截、真实 Glitter 文件拒绝后字节不变、原生仍可重新打开 Glitter、普通三档的密码与密钥文件组合解锁、原生条目与附件，以及普通库刷新不产生误同步状态。

本地证据目录为工作区 `.codex-tasks/glitter-client-defer-317/`。构建采用 JDK 17、Debug 与 x86_64 测试 ABI，设备复用公共 API 32 AVD `Monica_Issue136_API_32`。测试仅使用合成数据库。

最终构建日志为 `main-final-build.log`、`fdroid-build.log`，设备日志为 `main-final-regression.log`、`fdroid-final-regression.log`。运行器核对安装包 SHA-256、测试数量和设备设置恢复；[验证清单](GLITTER-CLIENT-DEFERRED-20261006.json)保留哈希及测试时间。首轮实际 32 项均通过，但运行器预期数量误填为 27；最终两版均以准确的 32 项重新验收，首轮不计入最终结果。

真实 Glitter 文件由保留的原生 API 创建；Android 使用错误密码也会先得到不支持提示，拒绝前后文件字节相同，随后原生 API 仍可用原密码和密钥打开。普通三档的组合凭据创建、重开和编辑回归均通过。

已检查普通版与 F-Droid 的实际三档渲染及旧保存目标提示。本次修改通过定向空白检查，专用 Glitter UI、预检和相关文案引用已清除；旧标识保留于格式兼容与拒绝逻辑中。

测试结束后已停止本任务启动的公共 AVD，保留注册、配置和数据盘。

设计记录见[三档本地 M3E Canvas](../design/tiga-three-modes-317/README.md)。旧 Glitter 验证文档保留历史并标明已暂缓接入。普通版、F-Droid、候选未发布说明及 F-Droid fastlane 24 已更新，仅按中文和英文分区。
